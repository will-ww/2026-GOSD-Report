## 编辑与核对入口

- `chapter5-v0.1r-editable-text.md`：按物理页组织的可编辑文本。页标题为恢复时新增；文本块保持 Poppler 提取结果，不润色、不重写、不自动规范化字符。
- `text-layer-layout.txt`：全章 `pdftotext -layout -enc UTF-8` 原样结果，包含换页符。
- `pages/page-01.txt` 至 `page-17.txt`：逐页原样文本，便于定位数字、句子与保留限制。
- `text-blocks.json`：第二种提取表示，含 PyMuPDF 文本块、行、文字片段、坐标、字体名称与链接位置。不含图片、字体文件或图形原件。
- `page-manifest.json`：输入指纹、逐页文本指纹、解压内容流指纹及 72dpi RGB 渲染指纹。后三者各有明确口径；内容流哈希不覆盖其引用资源，不能单独冒称完整页哈希。
- `figure-inventory.json`：14 张最终图的编号、标题、页码、小节和 PDF 实际链接。链接仅从 PDF 读取，未联网验证内容或可达性。
- `recovery-evidence.json`：版本比较、执行检查与未完成项。
- `scripts/recover_text.py`：固定输入指纹的恢复脚本。遇到其他版本立即停止。

## 离线重复提取

依赖 Python 3、PyMuPDF（本次 1.26.6）与 Poppler `pdftotext`。不需要字体二进制入库，也不联网。应输出到临时目录，再与本归档比较：

```sh
python scripts/recover_text.py /外部材料/第五章v0.1r.pdf --out /tmp/chapter5-recheck
```

脚本检查 PDF 整体指纹、17 页、14 张图题和逐页文本拼接完全一致。渲染指纹受渲染器版本影响，工具版本记录在清单中。恢复稿后续人工编辑后不应覆盖原始提取证据；请另存编辑版本并记录修订。

## 传输分片说明

为避免单文件上传超时，原 `text-blocks.json` 仅作无损 UTF-8 字节分片，交付位置改为 `text-blocks.parts/part-*.txt`，每片不超过 90,000 字节且不截断 UTF-8 字符。分片不是新的正文或数据版本，原内容、顺序、坐标与链接均未修改。`text-blocks.parts/index.json` 记录原文件与每片的字节数和 SHA-256。上述编辑入口中的 `text-blocks.json` 指还原后的文件，交付目录不再直接包含该大文件。

运行 `python source/chapters/05-recovered/scripts/restore_text_blocks.py`（从归档根目录）会先验证所有分片及合并后指纹，再默认写到归档根 `work/text-blocks.json`。可以用 `--output /明确路径/text-blocks.json` 指定目标；已有文件一律不覆盖。脚本仅还原字节，不执行还原内容或其他程序。原文件共 1,158,948 字节，SHA-256 为 `2420982cfbf7ca9079900902367577d005f137c8e18370cc1e49b6635b4376de`。已实测还原结果与分片前文件逐字节一致，并验证拒绝覆盖已有文件。

恢复提取脚本 `scripts/recover_text.py` 仍保持原样，会在指定输出目录生成未分片的 `text-blocks.json`；它不用于直接重写当前交付目录。当前 `SHA256SUMS` 覆盖分片后的实际交付文件。
