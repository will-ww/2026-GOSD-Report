# HF 与模型生态材料深度研究：证据边界、主张修订与章节重构建议

研究日期：2026-11-04。性质：供 GOSD 编委评审的研究底稿，不是第一章正式正文。主统计期：2025-07-01 至 2026-06-30。以下明确区分来源原文、研究判断与待实施分析；未声称已重新计算全量 Hub 数据。

## 一、先给结论

新材料值得改变报告的观察方法，而不是直接替换一套排行榜：

1. 从“发布了多少”推进到“谁提供基础能力、谁使其可用、谁持续复用、谁承担维护与治理”。模型发布者、基础模型作者、量化/适配者、工具维护者、实际采用者不能合并为一种贡献者。
2. 开放生态可以同时扩大参与与集中基础依赖。模型仓库数增长，不能单独证明权力分散；某个基础模型的衍生增长，也不能单独证明公共价值增长。
3. 下载只能成为受口径约束的分发/访问信号，不是用户数、生产部署数、收入份额或社会价值。关注、访问、复用、持续使用和公共结果应分别报告。
4. “开源 AI”须同时检查权利与修改所需材料；开放权重、宽松许可证标签、数据说明公开，均不能单独替代完整判断。
5. 建议保留已通过的六章四视角与“参与、供给、复用、治理与公共价值”主线，修改每章的证据接口；暂不据此改统计期或宣布整个报告方向已变。

最重要的两项数字或定义不一致与一项方法张力：Spring 的“前200模型占49.6%”与其引用论文的样本定义不一致；Summer 的 agent 份额与链接数据出现数量级差异；两篇材料对老模型下载采取不同解释与过滤策略，样本也不相同，不能判为对同一现象的直接互相否定。未经核对，不应把这些数字放入全书主张或总论图。

### 独立性与来源关系

- HF Spring → 直接引用 EOI；Spring作者与EOI部分作者重叠。二者相关结论只算一条研究链，不能称“两份独立研究证实”。
- HF Summer网页 ↔ GitHub Markdown：同一出版物的展示与版本载体。
- HF Summer → agent-usage：文字结论与底层数据可相互核对，但不是独立观测平台。
- RAM：研究设计来自不同团队，但底层依旧是HF下载；可验证测量稳健性，不能抵消HF平台覆盖偏差。
- FAccT2025：独立研究作者、不同变量（交互/社群），提供机制反例；仍未覆盖平台外活动。
- OSI：规范性来源。与经验材料的关系是“定义如何判断”，不是“证明哪一家公司合规”。

## 三、两项数字定义不一致与一项方法张力

### 3.1 静态Top200，还是逐周Top200并集？

HF Spring称前200个模型贡献49.6%下载；EOI方法§2说明，对265周分别取Top200，其并集为2,875模型，贡献49.6%。这是分母/样本定义冲突，不是四舍五入。

**处理决定建议：** 当前只采用EOI的明确方法表述，并注明与博客存在不一致。若要报告本期集中度，另行固定截至日与统计窗口，计算当期总下载排序的CR10/CR100/CR200，不借用历史Head Sample比例。不能据此拼接Summer另一口径的集中度形成“进一步恶化”趋势线。

### 3.2 老模型下载：噪声，还是长期基础设施？

EOI的滚动过滤仅计模型发布后一年内的下载，意在降低陈旧自动化负载；Summer则将老小模型持续下载解释为稳定流程依赖。两种解释均可能成立，但均不能仅凭下载年龄证明。

**研究判断：** 本书应把“自动化”拆为测试、镜像/重复获取、部署与业务流程依赖，而不是自动判为虚假。一个稳定组件可能少有讨论但长期运行；一个CI测试模型也可能承担基础设施验证价值，却不表示用户采用该模型的推理能力。

**建议的验证设计：**
1. A口径：原始下载；B口径：可获得时按用户/日去重；C口径：仅发布后一年内；D口径：按模型年龄、任务、格式和库分层。
2. 分别呈现排序与集中度变化，列出最敏感的对象；若B不可获得，明确缺失，不用A冒充B。
3. 对小型嵌入模型、CI常用模型、近期LLM各选少量病例，检查依赖声明、下载文件、CI引用与部署文档。来源可佐证“被某流程引用”，不能反推全体请求用途。
4. 对模型新品扩散与存量基础依赖使用两张图，而非选一个过滤器消灭另一类价值。

### 3.3 Agent份额：数量级不一致，且分母不足

Summer §6写Claude Code五月约64%；本次读取官方数据集中2026-05的pct_requests为6.405，unknown为59.8326。暂无法判定属于博客笔误、数据回填还是归因改变，故保留冲突，不自行更正原文。数据卡还明确仅覆盖已标记代理流量，4月存在推广偏差。

**处理决定建议：** 不采用“agents已经是Hub第一大用户”的排名性结论；仅保留“代理正在成为新的访问与操作主体，现有统计应识别其贡献及自动化偏差”这一研究议题。复核数据commit和博客版本后，五月至六月可作主期小窗探索；七月以后明确放期后观察，不画无说明的四至九月连续趋势。

## 四、对全书主张的实质修订

以下是本次研究提出的主张，不是文献原话；需要后续本期数据和案例检验。

### H1 从供给数量转向“可用供给链”

建议表述：开放模型的生态贡献不仅来自基础模型发布，也来自适配、压缩、评测、工具集成与持续维护。

- 可观察：基础/衍生关系、转换类型、首次适配时延、跨硬件支持、文档与许可继承。
- 反例：同一模型多格式镜像增加仓库数，但不一定增加独立能力；低下载的特定语言模型可能产生重要本地价值。
- 边界：衍生数量是再加工活动，不是创新质量。不要把量化、微调、合并、镜像统一称为“新模型创新”。

### H2 扩散与集中可能同时发生

建议表述：参与者和分发节点可以增多，同时基础模型家族、算力或托管依赖仍高度集中。

- 对同一数据分开计算仓库、发布者、基础家族集中度；保留未识别/跨国组织，不强制归国。
- 模型家族归因与分发者归因并列展示，不把两者下载相加。多父模型须说明分摊/完整计入方式。
- 反例：递归归因把下游价值全部归给原始家族，会抹去适配社区劳动；只看发布者又会遮蔽上游依赖。
- 边界：这些是特定平台的下载集中度，不等于经济市场份额、国家整体AI能力或主权可控程度。

### H3 复用价值必须允许多种时间尺度

建议表述：新模型扩散速度与旧组件持续依赖，是两种互补的复用信号。

- 新品可借鉴RAM的同龄同规模比较，进一步加任务和文件格式分组；总参数与激活参数不可混用。
- 存量则研究持续性、依赖范围和维护状态，不因发布超过一年自动归零。
- FAccT研究的“约六周”指单模型社区活动，不是生产使用寿命。跨模型迁移的社区可能持续存在。
- 边界：模型个体沉寂并不等于社群消失，社区讨论热闹也不等于生产采用。

### H4 开放应成为多轴条件而非单一标签

建议将附录B的判断单元固定到“模型版本＋相应许可证/文档版本”，至少记录：

1. 权重可获取性及是否需审批；
2. 使用、修改和再分发权利与限制；
3. 训练/处理代码及可获得程度；
4. 数据信息，包括数据来源、处理说明与不可共享部分的说明；
5. 复现和修改所需说明、依赖与环境；
6. 衍生发布的许可兼容和继承要求。

分别使用“已核实/声明存在/未提供/未核实/不适用”，不把缺失推断为违法或不合规；不把几个维度简单加成“开放总分”。EOI的数据透明度变量可帮助提出问题，但完整OSAID判定须重新逐项核查。

### H5 公共价值是结果问题，不是热度的别名

建议建立“开放条件→可达与可用→实际复用→可验证结果”的证据链，每个箭头都需要独立证据。

候选案例可包括小语种、本地/低资源运行、教育研究复现、公共服务、可迁移部署，但必须提供实际使用者、场景、约束和结果证据。下载多只能证明某种访问强度，不能直接证明节省多少成本、惠及多少人或改善公平。

## 六、建议先做的五个图与小型验证

这些是建议的下一步任务，尚未完成计算或绘制。

1. **证据与观测期地图**：横轴为时间，区分主期、历史、期后；每条来源显示真正观测窗口，而不是只显示发布日期。首章可先用，无须新的全量统计。
2. **从基础模型到可用供给的关系图**：展示基础模型、量化/适配、工具/框架、应用，边按具体关系标注；先用已核查小样本，避免假装完整生态地图。
3. **同一批模型的两种归因图**：发布者份额与基础家族份额并列；展示unknown而非删除。它可以直观解释“参与增加与上游集中共存”。
4. **下载口径敏感性图**：原始/可得去重/年龄过滤/任务分层下的排名与集中度变化，旁列覆盖率。拿不到历史快照时暂停趋势结论，只报告局限。
5. **开放条件证据矩阵**：少量代表性模型的版本级核查，每格链接许可证/代码/数据说明，不进行道德化或国家化总排名。

最小可复现数据字段建议：source_id、source_url、publisher、published_at、accessed_at、revision、observation_start/end、entity_id、entity_type、model_release_date、base_model_ids、relation_type、publisher_org、country_method、task、format、metric_name、metric_unit、aggregation、filter、attribution、value、missingness、period_class、claim_id。派生数据另存处理脚本与参数，保留原始字段，不覆盖来源数值。

## 七、评审需要决定什么

建议请作者确认新增研究选择，确认后进入第一章正式重构；此前首节样稿已完成，不重复启动。

1. 是否采用“供给链与复用机制”作为新增分析视角，保留既有章节结构？
2. 执行已批准的分窗规则：Spring、Summer按具体观测窗拆分，不整体并入主统计；此项无需重复审批。
3. 是否批准“下载/关注/衍生/部署/公共结果”分层，不用一个指标代表所有价值？
4. 是否将两项数字／定义不一致和一项方法张力作为证据审查范例，并暂缓相应强结论？
5. 是否先完成小样本谱系与开放条件核查，再决定全量重算范围？
