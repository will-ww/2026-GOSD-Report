# 全书主张地图

评审草案 v0.1 · 2026年11月4日

> 本稿待评审，不是已批准的写作基线或已验证的研究结论。


### 总体命题

拟议总体命题：AI时代的开源发展，应同时考察参与机会、开放供给、跨主体复用与治理条件；生态规模是起点，而非发展质量和公共价值的充分证明。

这是组织研究的判断框架，不是用现有数据已经证明的因果定律。全书应检验：不同地区、主体、技术领域和模型生态中，这些维度是否同步发展；哪些条件促进了持续创造；哪些环节仍缺乏证据。

主线分工：第一章定义问题与证据边界；第二章回答“参与和资源分布在哪里”；第三章回答“哪些主体形成何种影响”；第四章回答“技术如何组织与演进”；第五章回答“模型如何被供给、复用和开放”；第六章回答“各类主体能据此采取什么行动”。

### 第一章 从开放协作到公共价值

研究问题：为什么需要超越项目数量与榜单，研究开放协作的持续性和公共价值？

候选主张C1：公开发布只是起点，参与、维护、复用和治理共同决定成果能否持续被使用；数量或影响指标不能独自证明公共成效。

证据需求：有明确来源和时点的协作案例、模型衍生实例、开放许可与数字公共品标准；现有OSDGs和OSDI定义。案例用于解释观察维度，不能用少数成功案例推断所有项目。

小节安排：

- 1.1 共同创新与公共价值。比较持续共同维护与基于成果再创造两种机制，明确哪些是可观察事实、哪些仍待验证；作为第一章样节。
- 1.2 开源发展目标。说明参与、供给、连接、治理与公共价值分别对应何种问题；核查目标框架是否覆盖主线，避免把目标当成成效。
- 1.3 指标与观察方法。解释指标能回答什么、不能回答什么，并固定主统计期、平台范围、去重和缺失处理。

章间关系：为第二至第五章提供统一术语和边界，为第六章提供价值方向；不能先替后文宣布研究发现。

### 第二章 全球开源生态观测地图

研究问题：全球参与的空间分布、贡献强度和资源结构有哪些差异？规模增长是否意味着参与更加广泛和均衡？

候选主张C2：地区规模、贡献强度与项目影响可能呈现不同格局；发展机会不能由单一人数或总量推断。具体差异、方向和程度须经数据验证。

证据需求：同窗口去重开发者与协作事件、贡献指标、项目影响数据、地理覆盖与未知地区比例；必要的人口或组织规模分母；真实的治理及公共价值案例。

小节安排：

- 2.1 活跃地图。分开呈现绝对规模、活跃程度与变化，核对地理覆盖；作为第二章样节。
- 2.2 贡献地图。检验规模与人均或单位贡献是否一致，明确每个分母和样本边界。
- 2.3 项目影响地图。说明影响所在地区与开发者所在地区、项目归属地区之间的区别。
- 2.4 人才地图。分析持续参与、经验或角色结构，但不得仅凭账号活动推断完整能力。
- 2.5 资产地图。区分代码、模型和数据等资产类型及其计数边界，避免把镜像和派生视为独立原创。
- 2.6 多样性地图。只呈现有充分合法来源和定义的维度；未知项单列，不根据姓名等弱信号推断敏感身份。
- 2.7 治理与社会公益地图。结合明确的治理条件与案例证据，不以标记公益或采用开放许可替代社会成效评价。

章间关系：提供第三章主体比较的全球背景，为第四章选择技术生态案例，为第六章识别参与机会与支持缺口。

### 第三章 全球开源影响力排行榜

研究问题：哪些地区、企业、基金会与项目形成关键影响，影响结构是否集中、稳定或发生变化？

候选主张C3：不同主体的影响位置与变化机制并不相同；榜单可以识别关键节点和新进入者，但不能直接解释其质量、治理优劣或社会价值。

证据需求：统一定义与版本的影响指标、可比的历史榜单、组织和项目映射、别名与并购处理、机器人剔除规则、样本覆盖和新进入者筛选标准。

小节安排：

- 3.1 行政区划。分析地区影响与参与规模之间的关系；与第二章分工为“主体位置与变化”，避免重复地图；作为第三章样节。
- 3.2 企业。区分项目归属、员工贡献和生态协作，检验企业影响的集中与分布。
- 3.3 基金会。说明基金会项目组合与治理角色，不简单把托管项目影响等同基金会自身贡献。
- 3.4 项目。结合排行、变化和代表案例解释影响来源，说明单仓与多仓项目边界。
- 3.5 新势力项目。定义增长窗口、起始基数和筛选条件，防止低基数增长或短时热度主导判断。
- 3.6 大模型。明确排名对象是模型、模型家族还是仓库，以及与第五章模型网络指标的关系。

章间关系：为第四章解释关键主体和项目在技术生态中的位置；为第五章提供模型主体观察，但不重复其衍生网络分析。

### 第四章 全球开源技术全景洞察

研究问题：AI及其支撑技术的创新活动如何组织，技术分类、项目协作与生态演化之间存在怎样的联系？

候选主张C4：技术发展不能只由热门项目排行解释，需要联合观察功能分层、主体协作与跨期变化。是否存在“AI带动基础软件重组”等更强判断，必须由跨领域和跨期证据检验。

证据需求：版本化技术分类、分类依据和多标签处理规则；项目样本、协作或依赖关系、影响轨迹、真实案例和外部技术材料。分类图是解释结构的工具，不自动证明生态成熟度。

小节安排：

- 4.1 Agentic AI。以功能分层、项目位置和协作变化展示如何从技术全景形成洞察；作为第四章样节。
- 4.2 AI大模型。聚焦技术栈和工具生态，与第五章的模型供给、派生和开放条件分工。
- 4.3 云基础设施。检验AI工作负载与基础设施项目演化之间的关系，避免仅凭同时增长推断因果。
- 4.4 数据库系统。比较数据系统类别和使用需求变化，明确所选项目代表的范围。
- 4.5 RISC-V。关注开放指令集、实现与工具生态的差异，不能将开放规范等同所有实现开源。
- 4.6 PyTorch基金会。以治理和项目组合组织技术生态案例；其与前五节不属于同一分类层级，应在章首说明这是组织型生态案例，是否保留现标题待评审。

章间关系：解释第二、第三章宏观与主体变化背后的技术结构；向第五章过渡时聚焦模型成为可复用资产的机制。第四章现行目录和网页部分内容仍含框架或待补分析，不能以已有章节标题推定其证据已经完备。

### 第五章 全球开源大模型发展洞察

研究问题：模型由谁供给，如何被继续开发，开放条件是否足以支撑可及、可复现与负责任使用？

候选主张C5：模型发布、下游复用和开放条件是三个不同维度；模型数量增长不必然等于广泛采用，网络影响增强也不必然等于更完整开放。

证据需求：平台模型元数据、发布时间、发布主体、基础模型声明、模型卡与许可证、训练与评估材料可得性；HF官方观察与相关研究用于交叉验证和解释，不直接并入同口径样本。

小节安排：

- 5.1 供给与贡献。区分原始模型、衍生模型及发布主体，明确数量、增长和去重边界；作为第五章样节。
- 5.2 网络与影响力。分析基础模型与下游关系、集中程度及跨地区联系；说明关系声明的缺失和不确定性，不能将连线等同经验证训练过程。
- 5.3 开放条件与分级。按权重、代码、数据、许可和评估资料等维度记录开放条件；分级规则、未知信息和判定日期公开，不把“开放权重”直接称为完整开源。

章间关系：把第一章的再创造机制转为模型生态分析；与第三章的模型主体排名、第四章的技术工具生态互补；为第六章提出可及性、透明度和复用支持建议。

### 第六章 未来展望与行动建议

研究问题：依据本报告已经验证的证据，不同主体应优先采取哪些行动，行动成效如何持续观察？

候选主张C6：行动重点应依据实际发现确定，并分别指向参与能力、可维护开放供给、透明治理与跨主体协作；不能把预设口号包装成数据结论。

证据需求：第二至第五章的已验证发现、受影响主体、已有治理或实践案例、可操作资源与约束。每条建议至少链接一项前文证据，明确适用范围和不确定性。

小节安排：

- 6.1 核心洞察与趋势展望。只汇总已验证的核心发现，区分报告期内结果、期后观察与情景推演；作为第六章样节。
- 6.2 政府与国际组织。围绕公共投入、基础能力和跨境合作提出有证据依据的措施，不给出无依据的统一国家处方。
- 6.3 企业与组织。围绕长期维护、开放策略、人才与协作机制提出措施，并说明投入责任和风险。
- 6.4 社区与全球合作。围绕贡献者进入、维护者支持、透明治理和可复用资产提出措施，避免将责任全部转给志愿者。
- 6.5 结语。回到全书问题，说明本年度得到什么认识、什么仍不知道、下一轮需要追踪什么。

章间关系：承担证据汇总与行动转译，不成为新增且未验证数据的集中入口。现有“三项任务、九条建议”可作为候选结构，是否原样保留由前文证据和评审决定。


## 跨章一致性


### 跨章不重复的职责

参与规模和地区结构主要归第二章；主体排行和位置变化主要归第三章；技术类别和协作演化主要归第四章；模型供给、派生与开放条件主要归第五章。确需复用同一图或数据时，采用一致的定义与版本，并说明新的分析问题，不重复整段论述。

第一章中的案例只承担概念引入，完整实证放在对应研究章。第六章的每条主要建议应回链已验证发现，不能出现前文从未论证的新主张。

### 主张的最小记录格式

每项主张建议记录：编号、所属章节、研究问题、候选判断、当前状态、主要证据及版本、反证或限制、图表位置、关联行动建议。状态采用“待检验、证据支持、需收窄、不支持”四类。对读者只呈现适当且自然的研究说明，不暴露不必要的内部过程记录。
